# TaskFlow API — CLAUDE.md

## Project Overview

Multi-tenant REST API for team task management, built with Fastify 5 + TypeScript.

Domain: a **User** joins a **Workspace** through a **Membership** (which carries the `Role`). A workspace owns **Projects**, a project owns **Tasks**. Auth is JWT + a Redis token blacklist.

**Authorization always walks the chain `task → project → workspace → membership`.** `Task.userId` records who created the task — it is audit data and must never be used as an access check (see `docs/PRINCIPLES.md`).

## Key Conventions

- **Validation**: Always use Zod schemas defined in `*.schemas.ts`. Never validate manually inside route handlers.
- **Type provider**: Use `fastify.withTypeProvider<ZodTypeProvider>()` per-plugin so `request.body` is fully typed.
- **Auth guard**: every protected plugin does `app.addHook('preHandler', fastify.authenticate)` — it applies to all routes in the file.
- **Membership guard**: routes with `:workspaceId` in the path add `preHandler: fastify.requireMembership('<MIN_ROLE>')` **in the route options, never via `addHook`** — `addHook` would also hit `POST /`, `GET /`, `GET /trash`, which have no `:workspaceId`. See "Authorization layer" below.
- **Prisma access**: Only inside `*.repository.ts`, imported from `../../lib/prisma`. Never in services/routes.
- **Imports**: local imports are written **without a file extension** (`'../../lib/prisma'`). This works because `tsconfig` uses `"moduleResolution": "bundler"` and dev runs on `tsx`. Consequence: `tsc` is a **typechecker only** — the production build must go through a bundler (tsup/esbuild), which rewrites specifiers. Never `tsc`-emit and run the output with bare `node`. See `docs/PRINCIPLES.md` → `2026-08-11 · Імпорти без розширення`.
- **Generated code** (`src/generated/**`) is gitignored, prettier-ignored and eslint-ignored. Never edit it by hand — change the generator config in `prisma/schema/schema.prisma` and run `npm run generate`. A fresh clone must run `npm run generate` before `npm run typecheck`.
- **Line endings**: LF in the repo (`.gitattributes`). On Windows run `npm run lint:fix` if prettier complains about `␍`.
- **Services and repositories are classes**, instantiated once at the bottom of their own file:
  ```ts
  export class WorkspacesService {
    constructor(private readonly repo: WorkspacesRepository) {}
  }
  export const workspacesService = new WorkspacesService(workspacesRepository);
  ```
  The constructor is the point: it makes the repository swappable (Mongo in Task 2) and lets tests do `new WorkspacesService(fakeRepo)`. A class without constructor injection is just an object literal with ceremony. Repositories take no constructor arg — `prisma` is not their dependency, it is their implementation. **Never pass a class method as a callback** (`arr.map(repo.create)`) — `this` is lost; always call through the instance.
- **Routes stay functions** (`FastifyPluginAsync`) — Fastify's contract is a plugin function; a class would only wrap it.
- **Object parameters** when a method takes ≥2 arguments, or any two arguments of the same type in a row (`{ id, userId }`, not `(id, userId)` — the compiler cannot catch a swap). A single argument stays positional. Shared shapes live in `*.types.ts` (`MemberScope`, `ActorContext`). Never spread a scope into write data (`{ ...scope, role }`) — build write-models field by field; a scope means "who is asking", not "what to create".
- **Same shape ≠ same meaning.** Two interfaces with identical fields stay separate when they answer different questions (`FindActor` = "what role does this user have?" — the input; `ActorContext` = the answer, including `role`). A query's input must never require what the query returns.
- **`interface` for hand-written object shapes, `type` for derived/mapped/union types.** Write the shape out explicitly rather than `interface X extends Partial<Pick<...>> {}` — an empty interface body is an ESLint error, and a comment inside it does not count as a member.
- **No test framework yet** — `npm test` exits 1.

## Layering & Error Handling

> Rationale and the reasoning behind each rule live in `docs/PRINCIPLES.md`. These are the enforced rules.

**Dependency direction (one way only):** `route → service → repository → Prisma`.

- **route** (`*.routes.ts`): thin. Zod schema, guard in `preHandler`, read `request.user.id` / `request.membership.role`, call one service, set HTTP status. No business logic, no `try/catch`, no Prisma. The service never reads `request` itself — the route passes the role in explicitly (`ActorContext`).
- **service** (`*.service.ts`): business logic. Must NOT import `fastify`, use `req`/`reply`, or touch `Prisma`/`prisma`. Maps API DTO → persistence write-model. Throws domain errors.
- **repository** (`*.repository.ts`): the ONLY place that imports `prisma`/`Prisma`. Translates DB-specific failures (e.g. `P2002`) into domain errors.

**Errors:**

- Domain errors extend `AppError` (`lib/errors.ts`) with `statusCode` + `code`. Throw them — never `reply.status(4xx)` inside a handler.
- One central `setErrorHandler` maps everything to the envelope `{ error: { code, message, details? } }`. Stack traces go to logs only, never to responses.
- **Response schemas list exactly what the route can emit.** 2xx → entity schema; every 4xx → `errorResponseSchema` (a 4xx declared with an entity schema fails serialization and turns into a 500). `400` belongs on every route with `params` or `body` — Fastify throws it during validation, before the handler runs.
- **`update` / `delete` throw `P2025`** when `where` matches nothing (unlike `updateMany`/`deleteMany`, which return `{ count: 0 }`). Every such call in a repository is wrapped in `try/catch` and translated: `NotFoundError`, or `ConflictError` when the row exists but is in the wrong state (permanent delete of a workspace that is not in the trash). Services then don't null-check the result.
- `instanceof` works only against a real runtime class (`AppError`, `Prisma.PrismaClientKnownRequestError`). NOT against type-only interfaces (`FastifyError`) — narrow those with a single boundary cast.

**Types per layer (DRY with judgment):** API shape (`*Body`, `z.infer`) and persistence write-model (`*.types.ts`) stay SEPARATE even when they look alike — they change for different reasons (e.g. `dueDate` string↔Date; `userId` absent in body, added from JWT in the write-model for security).

**Partial updates:** build the patch with `if (input.x !== undefined)`, never truthy `&&` — truthy silently drops valid `''` / `null` / `0`.

**KISS/YAGNI:** repository translating a DB error straight to a domain error is fine. Add an intermediate neutral-error layer only on the 3rd real case (rule of three), not the 1st.

## Data Models

`User ──< Membership >── Workspace ──< Project ──< Task`

### User

```
id          String   (uuid, PK)
email       String   (unique, validated email)
password    String   (bcrypt, min 6 chars)
createdAt   DateTime
tasks       Task[]
memberships Membership[]
```

### Workspace — the tenant boundary

```
id        String    (uuid, PK)
name      String    (min 1 char)
slug      String    (UNIQUE — pretty URLs /w/acme-inc)
createdAt DateTime
updatedAt DateTime
deletedAt DateTime? (soft delete)
members   Membership[]
projects  Project[]
```

### Membership — explicit join model (carries `role`, so it is a real entity)

```
id          String    (uuid, PK)
role        Role      (default MEMBER)
userId      String    (FK → User, cascade)
workspaceId String    (FK → Workspace, cascade)
createdAt   DateTime
updatedAt   DateTime

@@unique([userId, workspaceId])   # one membership per user×workspace — DB-level invariant
@@index([workspaceId])            # leftmost-prefix: the @@unique already covers userId
```

### Project

```
id          String    (uuid, PK)
name        String
workspaceId String    (FK → Workspace, cascade)
createdAt   DateTime
updatedAt   DateTime
deletedAt   DateTime? (soft delete)
tasks       Task[]

@@index([workspaceId])
```

### Task

```
id          String      (uuid, PK)
title       String      (min 1 char)
description String?
status      TaskStatus  (pending | in_progress | completed)
dueDate     DateTime?
projectId   String      (FK → Project, cascade)  ← authorization goes through here
userId      String      (FK → User, cascade)     ← AUDIT ONLY: who created it
createdAt   DateTime
updatedAt   DateTime
deletedAt   DateTime?   (soft delete)

@@index([projectId])
```

Postgres auto-indexes primary keys and `UNIQUE` constraints — **never foreign keys**. Every FK used in a `WHERE`/`JOIN` needs an explicit `@@index`.

## Multitenancy & RBAC

`Role` is hierarchical; the rank lives in a TS constant, never in the Prisma enum order (enum order carries no meaning).

```
OWNER 4  >  ADMIN 3  >  MANAGER 2  >  MEMBER 1
```

| Action                              | Minimum role |
| ----------------------------------- | ------------ |
| Permanently / soft-delete workspace | OWNER        |
| Update workspace                    | ADMIN        |
| Add members, change roles, kick     | ADMIN        |
| CRUD projects                       | MANAGER      |
| CRUD tasks                          | MEMBER       |
| View workspace / members, leave     | MEMBER       |

Invariants (enforced by `assertCanManage(actor, target, minRole)` in `lib/rbac.ts`):

- you can only touch someone **strictly below** you (`outranks`), and only grant a role strictly below your own → an ADMIN cannot create, promote to, or touch ADMIN/OWNER;
- consequence: nobody can touch the OWNER (no rank above it), so there is always exactly one OWNER;
- the OWNER cannot leave (409 "Transfer ownership first"). Ownership transfer is not implemented yet.

Switch to a permission-set model only when a role stops fitting the hierarchy (e.g. a `BILLING` role that pays but touches no projects). Until then a numeric comparison is enough.

### Authorization layer — two questions, two places

| Question                                                                | Where                                                        | Throws                                                               |
| ----------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| "Who am I in this workspace, and am I allowed on this endpoint at all?" | `requireMembership(minRole)` guard, route `preHandler`       | 404 not a member / workspace soft-deleted · 403 rank below `minRole` |
| "May I do this to **this particular** target?"                          | service, `assertCanManage(actor.role, target.role, minRole)` | 403                                                                  |

The guard does one `SELECT` on `Membership` (`membersRepository.findActor`) **before** the handler runs and puts `{ role }` on `request.membership`. Why a separate query instead of roles in `where`: a single `updateMany` with the role inside the filter returns only `count`, so "does not exist", "not a member" and "rank too low" all collapse into 0 → everything became 404. A separate lookup sees the difference.

Rules:

- **Roles never go into a repository `where`.** After the guard, repositories work by `id` (`where: { id, deletedAt: null }`), which also lets them use `update`/`delete` and return the entity.
- **404, not 403, for non-members** — a stranger must not learn the workspace exists.
- **The guard reads `:workspaceId`** — every workspace-scoped route names the param exactly that. It casts `request.params` (`as { workspaceId: string }`); a legal boundary cast because `preHandler` runs **after** schema validation.
- **`requireMembership('OWNER', { allowDeleted: true })`** only on `DELETE /:workspaceId/permanent` — the one route that must reach a soft-deleted workspace. Everywhere else the guard is the single place that filters `workspace.deletedAt: null`; repositories called after it do not re-check.
- **The guard sets a floor, the service decides on the target.** `DELETE /members/:memberId` has floor `MEMBER` (self-leave is allowed to everyone); ADMIN is required only in the "not me" branch inside the service. The service keeps `assertCanManage` even where the floor is already ADMIN — it must not rely on the route remembering the guard.
- **Lists across workspaces** (`GET /api/workspaces`, `/trash`) have no `:workspaceId`, so no guard — they stay scoped by `members: { some: { userId } }` in the repository.

## Soft Delete

`deletedAt DateTime?` on Workspace / Project / Task. Permanent delete is a separate, OWNER-only endpoint doing a real `delete`.

- **Cascade is manual, inside a transaction.** `onDelete: Cascade` is a DB rule for a physical `DELETE`; it does not fire on `UPDATE deletedAt`. The schema keeps `Cascade` for the permanent-delete path.
- **Cascade bottom-up** (tasks → projects → workspace) and share one `const now = new Date()` across all statements. Never filter children by a parent field you are changing in the same transaction — inside `tx` the change is already visible, so the child update matches zero rows and `updateMany` reports it silently.
- **The parent row uses `update`** (throws `P2025` → `NotFoundError`); permissions are proven by the guard before the transaction starts. **Children use `updateMany`**, which never throws on zero matches — fine here, a workspace with no projects is valid.
- **`deletedAt: null` lives only in the repository** — including inside nested `include`, which is where it is most often forgotten (`projects: { where: { deletedAt: null } }`).
- **Freeing the slug**: on soft delete rewrite it (`deleted-${id}-${nanoid(6)}`) so a new workspace can reuse the name. A partial unique index (`WHERE deletedAt IS NULL`) is deliberately not used — Prisma cannot express it, and raw SQL causes permanent drift.

## Scheduler

`initScheduler()` in `src/lib/cron.ts` runs every minute and logs `console.warn` for any `pending` task whose `dueDate` is in the past.

## Adding a New Module

1. `<name>.schemas.ts` — Zod request/response schemas (+ `z.infer` types). Build them from the generated `*Schema` (`.pick`/`.omit`/`.partial`/`.extend`) so they follow the DB. Never expose `deletedAt` outside the trash endpoints.
2. `<name>.types.ts` — persistence write-models and shared param shapes (`*Scope`).
3. `<name>.repository.ts` — `export class <Name>Repository` + a singleton at the bottom. The only Prisma access; translates DB errors (`P2002` → `ConflictError`).
4. `<name>.service.ts` — `export class <Name>Service { constructor(private readonly repo: <Name>Repository) {} }` + a singleton wiring in the repository. Business logic, throws domain errors.
5. `<name>.routes.ts` — thin `FastifyPluginAsync` (schema + call service). `app.addHook('preHandler', fastify.authenticate)` once; `preHandler: fastify.requireMembership('<ROLE>')` per route for anything under a workspace.
6. Register in `src/app.ts`: `app.register(<name>Routes, { prefix: '/api/<name>' })` (workspace-scoped modules: `'/api/workspaces/:workspaceId/<name>'`) and add a Swagger tag.

Two traps worth re-reading before you commit:

- **`try/catch` around a promise without `await` is dead code** — the rejection happens after the `try` block exits. In a repository catching `P2002`, write `return await prisma.x.create(...)`. This is the rare case where `return await` is mandatory.
- **A function that always throws must be annotated `: never`**, otherwise TS infers `void` and breaks every caller that forwards its result.
- **A promise without `await` is not a check.** `this.repo.findActor(scope);` on its own line starts a query and throws the result away — the code below runs as if access were granted. TS and ESLint both stayed green on this exact bug.
- **`skipLibCheck: true` also skips your own `.d.ts`.** If a type from `src/types/*.d.ts` behaves oddly, run `npx tsc --noEmit --skipLibCheck false` — an unimported `Role` there was invisible otherwise.
